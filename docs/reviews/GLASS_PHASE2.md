# Liquid Glass phase2 — local rendering work, no push

Reference: owner MRiOS screenshots, especially translucent folder/library surfaces, fine rim and wallpaper tint. Original implementation; no reference icons/code copied. Geometry, Control Center/dock/dashboard structure and controls remain outside this phase.

Changed rendering files: GlassSurface.java, IosStyle.java, new GlassBackdrop.java; LauncherActivity.java only receives wallpaper-cache publication and destruction hooks in this phase. Other uncommitted Settings/controls/version changes predate this phase and were preserved, not treated as phase2 work.

Java Canvas/API26-compatible implementation, API27 target verification. No RenderEffect/RuntimeShader, live screen capture, refraction or backdrop capture of apps/video. The wallpaper's center-crop transform is mapped using the background View's screen location. Non-View drawable callbacks fall back to centered material texture; floating-window exact registration still needs inspection.

Configuration via engine preferences (no new Settings UI): glass_quality0 LOW/1 BALANCED default/2 HIGH; glass_tone0 AUTO/1 LIGHT/2 DARK. Existing glass_style0 Glass/1 Transparent/2 Solid remains supported. Quality changes take effect when the wallpaper is reloaded or the Activity recreated. Direct appearance-preview constructor has a gradient fallback without wallpaper cache.

Frost cache maximum long edge128/224/320px, three separable box-blur passes off the UI thread, radius2/4/6 cache pixels. One active blurred bitmap per Activity; peak includes old/new cache during replacement plus two temporary pixel arrays during preparation. Maximum active bitmap <=64/196/400KiB for square LOW/BALANCED/HIGH inputs. Arrays/bitmap are not allocated from draw(). Shader/path allocation occurs on bounds or cache revision changes. Image changes invalidate attached drawables through weak references; obsolete results obey the existing wallpaper-generation check. No forced GC/recycling of bitmaps that Canvas may still reference.

Surface appearance: wallpaper-average tint, Light/Dark base, gradient body, soft sheen/radial reflection, white graduated rim, two inset shadow bands plus existing View elevation where present. Shadows are an approximation inside drawable bounds, not a new exterior blur buffer. Light mode retains an ink tint because existing white foreground labels are unchanged; contrast is not WCAG-certified. Solid skips texture and reflection.

Validation artifacts: GlassRenderChecks and LegacyGlassSurface (original prior renderer retained only as a test fixture). Comparison uses Android software Canvas with synthetic light/dark blue, pink and neutral backgrounds: old renderer left, new renderer right. This verifies bounded caches and cache identity over repeated draws; it does not prove absence of every framework allocation, full UI geometry, GPU rendering, dialog alignment, FPS or head-unit memory/performance. No owner screenshots are bundled as test art.

Final validation: assembleDebug, assembleDebugAndroidTest and lintDebug succeeded; lint0 errors/45 warnings (including existing application warnings). Matching-signed API27 emulator fixture passed30 checks on the final build. Visual inspection of the comparison confirms blurred test patterns, tinted materials and graduated rims on six light/dark blue/pink/neutral cases. Full dashboard screenshot was blocked by an emulator com.android.systemui ANR; it is not evidence of an iDash crash, nor a passing full-window GPU test. No hardware FPS/RAM/readability or floating-dialog registration certification. No commits or pushes performed.
