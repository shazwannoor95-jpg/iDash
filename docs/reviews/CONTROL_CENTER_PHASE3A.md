# Phase3A landscape Control Center — local only

Files in this phase: QuickControls.java (composition), new CapsuleSlider.java and ControlGlyph.java (original Canvas components), new ControlLayoutChecks.java and vertical-touch update in SettingsChecks.java (tests). GlassSurface/GlassBackdrop/IosStyle are reused without changes. Other uncommitted dashboard/Settings/version work belongs to earlier phases. No commit, push or release artifact update.

Layout: grouped2x2 connectivity card, media empty-state card, vertical brightness/volume capsules, Focus and circular utility row, retained quick actions. Content fits without scrolling at1024x600 and800x480. Dialog wraps content; smaller height uses a reduced middle row and single-line permission status. Important targets >=48dp in tested profiles. Extremely small viewports or enlarged fonts outside tested profiles can still require follow-up; no blanket all-screen claim.

Connections are links to Android settings, not privileged toggles. Wi-Fi/Bluetooth/airplane active color follows Android-reported state; unavailable/permission-limited state stays grey. Android Bluetooth adapter state is not certification of OEM hands-free status. No SSID/device identity is collected. Volume and brightness retain existing public Android callbacks/permission and automatic-brightness checks. CapsuleSlider extends SeekBar, retains its listener/accessibility interface, maps local Y to progress and tracks drag state. Settings, Panel, Wallpapers and brightness-access/Display links remain connected.

Media displays Not Playing / No active session linked, with disabled transport controls. Focus, flashlight, camera, timer and calculator are explicitly disabled previews. No media-session, notification-listener, camera, flashlight, DND or new privileged system-control logic is added. Settings utility is connected. Preview state is not a claim that device hardware is absent.

Rendering uses shared wallpaper frost and Dark Glass for contrast; sliders have clipped bright fill and original vector sun/speaker. No bitmap allocation in CapsuleSlider.onDraw or ControlGlyph.onDraw; no new native library/dependency. State discs rebuild gradients only when state changes. Existing cache caps64/196/400KiB remain shared, but total memory, GPU overdraw, FPS and thermal behavior were not profiled on a1GB device. Drawing uses Canvas APIs available onAPI27; Java-only additions do not introduce an ARM64 dependency. ARM32 physical execution remains untested.

Build: assembleDebug, assembleDebugAndroidTest and lintDebug PASS,0 errors/49 warnings. Final API27 emulator checks:36 layout assertions PASS at1024x600 and36 PASS at800x480, checking key bounds/clipping,48dp touch targets and explicit disabled previews. Actual emulator screenshots saved to /workspace/output/idash-control-center-1024x600.png and idash-control-center-800x480.png. An existing emulator SystemUI ANR dialog was visually identified and dismissed before testing; it was not counted as an iDash fix. Emulator screenshots are not simulations and do not certify physical performance.

Regression:27 Settings/control assertions PASS on the final APK after adapting the test gesture to vertical sliders. Tests exercised actual Android media-volume changes, brightness writes with temporary emulator app-op access, disabled brightness without access, preservation of Automatic mode, appearance/preferences and the retained Panel action. Test finally restored brightness/mode/volume and reset the temporary app-op before instrumentation finished. This validates Android settings/API behavior on the emulator, not OEM FM volume or physical backlight output.
